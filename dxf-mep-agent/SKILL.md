# DXF-MEP Analyzer — Автоматизированный агент анализа MEP-чертежей

## ТРИГГЕР

Запускай этот skill когда пользователь:
- Упоминает DXF файл / чертёж / проект
- Говорит про инженерные сети, водопровод, электрику, вентиляцию
- Просит анализировать чертежи, считать трубы, находить конфликты
- Называет MEP (Mechanical, Electrical, Plumbing)

## АВТОМАТИЧЕСКИЙ WORKFLOW — ДЕЛАЙ БЕЗ ВОПРОСОВ

### ШАГ 1: Спроси файл (ОДИН вопрос, потом действуй)

```
Укажите путь к DXF файлу для анализа. Я автоматически:
• Определи масштаб и слои
• Посчитаю оборудование по категориям
• Измерю длины трубопроводов
• Найду конфликты между системами
• Сгенерирую отчёт
```

### ШАГ 2: Валидация файла (автоматически)

Проверь что файл существует через `mcp_windows_mcp_FileSystem(mode="info", path=<путь>)`. Если не найден — скажи об этом. Не пытайся анализировать несуществующий файл.

### ШАГ 3: Запуск MCP инструментов (автоматически, без вопросов)

Используй инструменты dxf-mep-analyzer в этой последовательности:

1. **initialize_analysis** → загрузить файл
   ```json
   {"dxf_path": "<путь>", "scale_hint": null}
   ```

2. **scan_layers** → определить слои (если есть) или выведи список слоёв из результата initialize

3. **count_equipment_on_layer** для КАЖДОГО слоя по порядку:
   ```json
   {"layer_name": "<имя_слоя>"}
   ```

4. **get_pipe_lengths** для слоёв с трубами (M-PIPE-*):
   ```json
   {"layer_name": "<слой>", "pipe_patterns": ["*"]}
   ```

5. **extract_annotations_by_pattern** — собрать диаметры и уклоны:
   ```json
   {"pattern_type": "diameter", "layer_name": null}
   {"pattern_type": "slope", "layer_name": null}
   ```

6. **detect_2d_clashes** между каждой парой слоёв разных систем:
   ```json
   {"layer_a": "<слой1>", "layer_b": "<слой2>"}
   ```

### ШАГ 4: Показывай прогресс (не скрывай работу)

После КАЖДОГО инструмента пиши пользователю:

```markdown
🔄 **Анализ слоя M-PIPE-WATER:**
| Параметр | Значение |
|----------|----------|
| Оборудование | 15 единиц |
| Трубы Ø50 | 42.3 м (8 участков) |
| Трубы Ø100 | 28.7 м (4 участка) |
```

### ШАГ 5: Сгенерируй финальный отчёт (автоматически)

После завершения всех проверок сгенерируй Markdown-файл через `mcp_windows_mcp_FileSystem(mode="write")`:

**Имя файла:** `<имя_проекта>_report.md`
**Содержание:** полный отчёт по шаблону ниже.

```markdown
# Отчёт анализа MEP-чертежа: <имя_файла>

## Общая информация
| Параметр | Значение |
|----------|----------|
| Файл | `<путь>` |
| Масштаб | 1:<масштаб> |
| Слоёв | N |
| Объектов | N |

## 📦 Оборудование по слоям
...

## 📏 Трубопроводы
...

## ⚠️ Конфликты между системами
...

## 💡 Рекомендации
- Если конфликтов > 5: КРИТИЧЕСКИ — требуется перепланировка трасс
- Если конфликтов > 0: Требуется согласование с проектировщиками
- Если конфликтов = 0: Чертеж прошёл проверку без замечаний
```

### ШАГ 6: Предложи сохранить отчёт (ОДИН вопрос)

```markdown
✅ **Анализ завершён!**

Отчёт сохранён в файл. Сохранить также на рабочий стол? [Да / Нет]
```

При ответе "Да" — скопируй файл через `mcp_windows_mcp_FileSystem(mode="copy")`.

## КАТЕГОРИИ СЛОЁВ (автоопределение)

| Паттерн в имени | Категория |
|-----------------|-----------|
| PIPE, WATER, SANITARY, SEWER | 🚿 Водопровод |
| CABLE, ELEC, POWER, LIGHTING | ⚡ Электрика |
| DUCT, VENTILAT, HVAC-DUCT | ❄️ Вентиляция |
| Остальные | ❓ Не определено |

## ОБРАБОТКА ОШИБОК (без пауз)

- **Файл не найден** → скажи об этом и попроси другой путь
- **Пустой слой** → пропусти, напиши "Слой пуст — пропущен"
- **Ошибка масштаба** → используй 1:100 как дефолт
- **Нет труб на слое** → напиши "Трубы не найдены" и продолжай

## ВАЖНО — НИКОГДА НЕ ДЕЛАЙ

❌ Никогда НЕ открывай/не читай DXF файл напрямую! → вызывает context injection refused (1.6M токенов vs 32k лимит)
❌ Никогда НЕ используй read_file, browser_read или FileSystem(mode="read") на DXF файлах!
❌ Никогда НЕ прикрепляй DXF файлы к контексту — работай ТОЛЬКО через MCP инструменты (initialize_analysis → count_equipment → get_pipe_lengths)
❌ Не проси пользователя писать JSON-команды
❌ Не требуй запускать скрипты вручную  
❌ Не говори "выполните следующую команду"
❌ Не показывай технические детали (исключения, пути к модулям)
✅ Всё делай автоматически — от загрузки файла до отчёта через MCP инструменты (только структурированные данные <5k токенов на вызов)
