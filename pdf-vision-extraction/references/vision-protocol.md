# Vision-протокол: PDF без текстового слоя — детали

## Признаки того, что нужен именно этот протокол
- `probe`/`get_text()` → пустой текст на страницах с видимыми таблицами.
- Страницы могут быть повёрнуты (rotation=270°) — pymupdf рендер это учитывает сам.
- tesseract v5.4 на таких документах даёт мусор — не тратить время, сразу vision.

## Чекпоинты и возобновление
- Per-page JSON (`data/p{N}.json`) — единственный источник прогресса. При возобновлении: перечислить файлы в data/, найти первую отсутствующую страницу, продолжить с неё.
- В финальном отчёте при прерывании всегда указывать: что на диске (диапазон страниц), что прочитано но не записано, что осталось.

## Кропы: геометрия и размеры
- Строка таблицы ≈ 0.02–0.03 высоты страницы; брать полосу y0..y1 с запасом ±0.02 вокруг строки.
- `Matrix(5,5)` + downscale ≤1200px — рабочий баланс для строк; `Matrix(8–10x)` только для отдельных чисел/букв.
- Если кроп не попал в строку (видны соседние) — сдвинуть y на ±0.03 и переснять, не уменьшать зум.

## Примеры верификации из практики (КОРОЛЕВ 2.4)
- `SHKOP-DV-1x15/380-K` vs `ШКРП...`: кроп подтвердил SHKOP; кросс-проверка по сданным томам с текстовым слоем дала паттерн DV=высокая мощность / DP=низкая.
- `FPV-(I20)` → (120): имя клапана EI120 + все другие FPV коды (60)/(120) — систематическая потеря «1».
- L=21720 vs 2120: первый проход потерял «7»; tight crop Matrix(5,5) на имя+код решил.

## После всех страниц
Агрегация per-page файлов → rows.json (структурные паттерны из соответствующего скилла, например spec-pdf-csv) → build → анализ (count vs raw, пустые имена, дубли, артефакты) → уведомление в Lark.
