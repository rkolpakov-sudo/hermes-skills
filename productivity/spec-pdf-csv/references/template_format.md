# Формат шаблона PDF-спецификации (template_format.md)

> Справочный файл для `detect_template.py` и `extract_spec_custom.py`.
> Читать при создании или ручной корректировке шаблона.

## Назначение

Когда `find_tables()` не может распознать таблицу (сложная вёрстка, нестандартная шапка),
шаблон задаёт **y-границы таблицы постранично** и **x-диапазоны для каждой колонки**.
Извлечение строк идёт через `page.get_text("words")` — координатный парсер.

## Ограничение (критическое)

| Условие | Работает? |
|---------|-----------|
| Страницы не повёрнуты (портрет/альбом, 0°) | ✅ Полностью |
| Страницы повёрнуты на 90° (ОВ — все листы) | ❌ Координаты — мусор. Использовать `find_tables()` |

## Формат JSON

```json
{
  "template_type": "y_window_x_columns",
  "name": "VK_внутреннее_водоотведение",
  "pages": [12, 13, 14],
  "y_windows": {
    "12": [122, 638],
    "13": [44, 728],
    "14": [44, 420]
  },
  "columns": {
    "poz": [60, 105],
    "name": [108, 495],
    "type": [495, 745],
    "code": [0, 0],
    "supplier": [745, 885],
    "unit": [885, 935],
    "qty": [935, 1000],
    "mass": [1000, 1060],
    "note": [1060, 9999]
  },
  "header_keywords": ["Поз.", "Наименование", "Тип"],
  "section_pattern": "СИСТЕМА\\s+К\\d+",
  "line_tolerance": 4.0,
  "column_row_min": 5,
  "footer_keywords": ["Лист", "Изм.", "Подп.", "Дата"]
}
```

### Поля

| Поле | Тип | Обязательное | Описание |
|------|-----|--------------|----------|
| `name` | string | ✅ | Уникальное имя шаблона (латиница/цифры/_) |
| `pages` | int[] | ✅ | Номера страниц (1-indexed) |
| `y_windows` | {string: [int,int]} | ✅ | y-границы таблицы для каждой страницы |
| `columns` | {string: [int,int]} | ✅ | x-диапазоны колонок: {имя: [x0, x1]} |
| `header_keywords` | string[] | ✅ | Ключевые слова для авто-определения шаблона |
| `section_pattern` | string | | Regex заголовков секций (СИСТЕМА К1/К2) |
| `line_tolerance` | float | | Допуск кластеризации слов в строки (pt) |
| `column_row_min` | int | | Минимум слов для фильтрации колоночного ряда |
| `footer_keywords` | string[] | | Ключевые слова футера (штамп листа) |
| `template_type` | string | | `"y_window_x_columns"` — идентификатор формата |

### Допустимые имена колонок

9 колонок (аналогично `extract_spec.py`): `poz`, `name`, `type`, `code`, `supplier`, `unit`, `qty`, `mass`, `note`.

Если колонка отсутствует — указать диапазон `[0, 0]` (парсер игнорирует).

## Создание шаблона

### Авто-детекция (скрипт)

```bash
python scripts/detect_template.py <pdf> --page 0 --confirm
```

Скрипт:
1. `page.get_text("words")` → получает слова с координатами
2. Cтроит гистограмму x-позиций → находит колонки (промежутки > 12pt)
3. Кластеризует y → находит y-окно
4. Анализирует содержимое колонок → определяет тип (poz/name/type/...)
5. Извлекает header_keywords из заголовочной зоны
6. Выводит JSON и спрашивает подтверждение

После подтверждения шаблон сохраняется в `templates/<name>.json`.

### Ручная корректировка

Человек может изменить x-диапазоны одной строкой в чате:

> «Колонка name — от 60 до 495, type — от 500 до 745»

Модель обновляет JSON и сохраняет.

## Использование шаблона

```bash
python scripts/extract_spec_custom.py <pdf> --template templates/<name>.json --out-dir .
```

Парсер:
1. Для каждой страницы: `page.get_text("words")` → фильтрация по y-окну → кластеризация в строки
2. Для каждой строки: раскладка слов по x-диапазонам колонок
3. Классификация через `classify()` из `extract_spec.py`

Результат: `spec_*.csv`, `spec_*_rows.json`, `spec_*_log.json` — тот же формат.
