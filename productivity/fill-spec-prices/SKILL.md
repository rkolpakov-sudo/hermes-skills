# Заполнение цен в спецификации из справочного файла

Заполняет колонку «Цена» в спецификации (ВОР, ведомость объёмов работ) значениями
из справочного файла с ценами. Справочник обычно содержит цены только на
УНИКАЛЬНЫЕ позиции (в спецификации наименования повторяются между разделами).

Триггеры: «заполни цены в спецификации X из файла Y», «проставь цены в ВОР»,
«fill prices in spec X from file Y». Имена файлов и колонки всегда разные —
структуру определять на каждом прогоне, всё параметризовано.

## When to Use

- Пользователь даёт два xlsx: спецификацию (ВОР) с пустой колонкой цен и
  справочник с ценами на уникальные позиции, и просит заполнить.
- Любая вариация: «проставь цены», «заполни стоимость», «подтяни цены из Y».

## Жёсткие правила пользователя (не спрашивать повторно)

1. **Заполнять ТОЛЬКО строки материалов** (в типовом ВОР колонка A =
   «материал»/«материалы»). Строки «работа» (СМР: Монтаж/Прокладка/Изоляция/
   Испытание) НЕ заполняются никогда — даже если цена на них есть в справочнике.
2. Цена «-» в справочнике → ячейку цены оставить ПУСТОЙ, а **всю строку залить
   красным** (FFC7CE).
3. Строка без позиции в справочнике → пустая, без заливки.
4. Структура файла сохраняется ПОЛНОСТЬЮ (объединения, формулы, форматы, шапка).
   Отменять объединения можно, но в этом сценарии не требуется.
5. Новый файл: `<имя исходного>_с_ценами.xlsx` рядом с оригиналом. Оригинал не
   изменять.
6. Цены копировать как числа без округлений.
7. После заполнения ОБЯЗАТЕЛЬНА верификация с реальным выводом (пользователь
   требует доказательств).

## Шаги

1. **Изучить структуру обоих файлов** (обязательно до вопросов/заполнения):
   - листы, размеры, объединённые ячейки (openpyxl или MCP excel);
   - найти колонку цен в спецификации (обычно H «Цена за ед., руб. с НДС») —
     проверить, что она пустая, кроме шапки;
   - найти колонки: тип строки (A), № (B), наименование (C), объём (G),
     формула стоимости `=G*H` (I);
   - в справочнике: колонка наименования (B) и колонка цены (H).
   - Учесть: в справочнике возможны дубли наименований (брать первую цену), цены
     могут быть строками («-», «757,514.47» с разделителями тысяч).
2. **Сопоставление по наименованию** с нормализацией:
   `" ".join(str(s).split()).lower().replace("ё","е")` (схлопывание пробелов,
   регистр, ё→е). Символы диаметра ⌀/Ø/∅/ø оставить как есть — они совпадают.
3. **Заполнить** скриптом `scripts/fill_spec_prices.py` (см. ниже) или openpyxl:
   - загружать спецификацию с `data_only=False` (сохранить формулы!);
   - после сохранения выставить `wb.calculation.fullCalcOnLoad = True`;
   - при заливке строки красным пропускать не-якорные ячейки объединений.
4. **Верифицировать** командой `verify` (та же утилита):
   - каждая заполненная цена == цене справочника (0 расхождений);
   - «работа»-строк с заполненной ценой == 0;
   - число красных строк == числу цен «-»;
   - объединённые ячейки и размер листа идентичны оригиналу;
   - формулы I (`=G*H`) на месте;
   - дополнительно открыть файл вторым парсером (MCP excel) и сверить несколько
     строк, включая пересчитанную стоимость.

## Использование скрипта

```bash
python fill_spec_prices.py fill "spec.xlsx" "ref.xlsx" --price-col G          # out: spec_с_ценами.xlsx
python fill_spec_prices.py fill "spec.xlsx" "ref.xlsx" --out "out.xlsx"       # явное имя
python fill_spec_prices.py verify "out.xlsx" "ref.xlsx" --orig "spec.xlsx"    # верификация
```

**ВАЖНО: колонка цены в спецификации бывает разной** — в ЖК1 это H, в ЖК2 уже G
(структура «Ед.изм., Объём, Цена, Стоимость» без колонки завода-изготовителя).
Всегда проверять шапку и передавать `--price-col`.

Параметры (структура типового ВОР по умолчанию):
- спецификация: `--type-col A`, `--name-col C`, `--price-col H`,
  `--row-types материал,материалы`;
- справочник: `--ref-name-col B`, `--ref-price-col H`;
- `--dash-color FFC7CE` (заливка строк с ценой «-»), `--start-row 2`.

Стратегии сопоставления (по порядку, пока не найдено):
1. **direct** — точное совпадение нормализованного имени (пробелы/регистр/ё→е);
2. **manual** — ручная карта `--manual-map file.csv` (строки `наименование;цена`,
   utf-8, `#` — комментарий) для позиций, которых нет в справочнике или где нужна
   конкретная цена (например «Труба из ВЧШГ ДУ 150мм» → взять раструбный вариант);
3. **strip** — снятие ведущего префикса `--strip-prefix "Монтаж "` (опечатки в
   имени, напр. «Монтаж Полотенцесушитель ДУ 20» → «Полотенцесушитель ДУ 20»);
4. **group** — восстановление фрагмента: имя начинается с ⌀/Ø/∅/ø (например
   «⌀150х4,5») + имя ближайшего родителя-группы, оканчивающегося на «:»
   («Труба … на грувлоках:») = полное имя. `--no-group-prefix` отключает;
5. **nospace** — fallback: совпадение по имени без пробелов (например
   «стальнойØ100» vs «стальной Ø100»). `--nospace` включает.

## Если в справочнике нет цен на часть позиций (второй проход)

По запросу пользователя сформировать файл **«для заполнения»**: все строки
материалов без цены (исключая служебные «Монтаж», «Материалы:»), с колонками
«Строка в ВОР | Наименование | Тех. характеристики | Ед. изм. | Объём | Цена, руб.»
(цена пустая). Пользователь заполняет цены (числа), помечает нерешённые «-» или
«проверить», возвращает файл.

Второй проход по команде пользователя:
1. Прочитать возвращённый файл: ключ — «Строка в ВОР» (колонка A), цена (F).
2. Для каждой числовой цены: проверить, что имя в ВОР на этой строке совпадает
   с именем из файла (защита от сдвига строк), что цена ещё не проставлена, и
   вписать значение в колонку цены (data_only=False, fullCalcOnLoad=True).
3. Расширить ручную карту `--manual-map` ценами пользователя и прогнать `verify`
   (иначе verify пометит их как «нет позиции»).
4. Позиции с «-»/«проверить»: искать в справочнике нечётко (difflib ≥ 0.55 и
   прямой поиск по ключевым словам); если совпадений нет — оставить пустыми и
   честно сообщить, что в справочнике их нет (заголовки групп/комплектов, новые
   типоразмеры). Не выдумывать цену по ближайшему аналогу с другим диаметром.
5. **Отметка «-» пользователя = НАЗВАНИЕ ПОДГРУППЫ, не заполняемая позиция**
   (заголовки «Водомерная вставка…:», «Водомерный узел N1…:», группы труб).
   Такие строки не включать в файл «для заполнения» и не ждать для них цен.
   Заполняемые — строки с реальными товарами (например патрубки с отметкой
   «проверить»). При генерации файла «для заполнения» исключать подгруппы
   (имя заканчивается на «:» / нет ед.изм. и объёма / отметка «-»).

## Pitfalls

- **openpyxl не считает формулы и не хранит кэш при сохранении** — после save
  формулы остаются, но без кэшированных значений; `fullCalcOnLoad=True` заставит
  Excel пересчитать при открытии. НИКОГДА не сохранять книгу, загруженную с
  `data_only=True` (формулы будут потеряны).
- **Заливка объединённых ячеек**: стиль виден только у якоря (верхняя-левая);
  заливка не-якорной ячейки не отображается. Пропускать не-якорные ячейки.
- **Строковые цены**: «-»/«—»/«–» = нет цены; «757,514.47» = 757514.47
  (парсить `float(s.replace(",",""))`).
- **«работа»-строка «Гидравлическое испытание трубопроводов»** есть в справочнике
  с ценой — несмотря на это, по правилу №1 в ВОР её не заполнять.
- Итоговые строки («ИТОГО», «НДС», «Детализация затрат») отсекаются фильтром по
  типу строки (колонка A пустая или другой тип).
- Проверка заполнения через MCP excel (excelize) дополнительно доказывает, что
  файл валиден и формулы пересчитываются.

## Верификация (обязательна)

Прогнать `verify` и показать пользователю таблицу: сколько строк заполнено,
сколько с «-» (красные), сколько без позиции, «работа»-строк заполнено = 0,
ошибок сверки = 0, структура идентична. Точечные примеры (3-5 строк) с ценами.
